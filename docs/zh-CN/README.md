# 判断框架是否适合你的任务

你有一个 Python 产品，希望让模型完成任务：接收输入、调用工具、以流的形式输出，并在用户停止任务或连接断开时保持清晰的状态。flops-agent 为这个过程提供运行时内核。模型、产品接口和存储后端仍由你选择。

**Reader question:** 框架应该负责产品的哪些部分？我该从哪里开始？

**Prerequisites:** 能运行 Python；不需要预先了解智能体术语。**Outcome:** 区分框架与产品的职责，选择一条能完成的学习路径。

## 明确边界

| 你的需求 | 框架提供 | 你需要提供 |
|---|---|---|
| 完成一次模型与工具的交互 | Runtime、Runner 和工具调度 | 模型客户端和工具业务逻辑 |
| 向浏览器增量投递结果 | 事件、订阅、SSE 编码和重放游标 | HTTP 路由、身份验证和客户端渲染 |
| 在下次请求中继续对话 | Session 和 Database 协议 | 持久化后端和用户隔离策略 |
| 停止、等待回答或在重启后恢复 | Run 状态、交互和恢复编排 | 产品入口、恢复上下文和工具幂等性 |

这不是部署后就能登录使用的托管聊天产品。仓库示例也不是监听端口的 HTTP 服务。先运行不需要模型账号的离线示例，再逐步替换产品边界处的实现，这比同时排查网络、身份验证和执行问题更容易。
